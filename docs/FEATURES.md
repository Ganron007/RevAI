## Quality gates & platform features

| # | Feature | What it does | Gate | Stage | Artifact |
|---|---------|-------------|------|-------|----------|
| G23 | **Indicator scrubber** (plan #42) | Removes indicator *values* from published report prose that no tool observed, so a report asserts only what the evidence supports. Reuses G19's verifier, replaces each ungrounded value with a named marker (`[registry path not observed in evidence]`), records every removal, and re-verifies — a scrub that silently fails to take effect is visible rather than assumed. The registry-path extractor tolerates segments containing spaces (`Windows NT`) and accepts trailing value-name suffixes (`...\Winlogon\Shell`). **Refuses to run against an empty evidence corpus** — absent and empty corpora behave identically, because an empty corpus makes every claim "unverified" and would delete the sample's own sha256 while reporting `remaining_unverified: 0` | always on | publish (master v2, technical v2/v3) | `report-*.json` `indicator_scrub`, `section-results-v3.json` `master_v3_indicator_scrub` |
| G24 | **Hollow-success detector** | The gate that decides whether a run produced a real artifact or a hollow one: report sidecars, verdict panels, verdict/label agreement, function-recovery result-vs-candidate counts, and stage-log needles. Discovers the publish sidecar instead of naming it; two reports that both parse no verdict panel now emit `verdict.panels_unreadable` rather than passing on nothing to compare; standard-path checks record `None` rather than `False` on the agentic path (`engine_path: "agentic"`), so a green agentic run is not marked false | always on | audit | `pipeline-audit.json` `stages.hollow_success` |
| G25 | **Run watchdog** (`scripts/run-watched.sh`) | Streams a run's stages, attributes each line to the stage that emitted it from the stage log, classifies the first anomaly with its stage, and can abort before the budget is gone. Exit contract: 0 = every stage rc=0, 1 = a stage failed itself, 2 = the watcher killed the run, 3 = usage/environment error. `--mode` overrides the inherited run mode; `--timeout-minutes` bounds the wall clock; `--skip-health-check`, `--no-reboot`, `--verify-parity` opt out of the pre-flight steps | operator-invoked | whole run | `logs/_watched_<sha12>.log` |
| G26 | **Deterministic indicator section** | Section 8 of the technical report is *rendered from* `iocs.json` rather than authored by the model, so indicator counts, values and confidence tiers cannot be prose-invented or dropped. Cross-checked against G19/G23 on the same case | always on | publish (technical v2/v3) | `REPORT-TECHNICAL-v2/v3.md` section 8, `iocs.json` |
| G27 | **Published-artifact hygiene** | Published markdown carries no provider or model name — `verdict.json` and `pipeline-audit.json` keep the real name because an auditor needs to know which model judged the sample, while every published `.md` emits `configured-llm`. Enforced from both directions: the evidence pack emits the public label, and a defensive redaction pass runs over every report because the model copies the string into its own prose | always on | publish + audit | `report-*.json` `model_names_redacted`, `docs/` hygiene scan (2,455 files) |
| G28 | **Indicator-first string sampling** | FLOSS's `static_strings` category — where plain registry paths, URLs and mutexes live — was sampled LAST, so a 80-string cap consumed by higher-priority categories left it contributing nothing. `win32k_dll`'s seven real UTF-16 registry paths (including `...\Winlogon\SpecialAccounts\UserList`) never reached the prompt, and the report reconstructed them from training data. Sampling is now shape-first (registry paths, URLs, IPs, emails, file paths, `Global\`/`Local\` mutexes, script/executable names) with the drop counts recorded so a truncated indicator set is visible rather than silent. Import-table noise (`kernel32.dll`) is excluded by design — the import table records those authoritatively | `REVAI_FLOSS_MAX_STRINGS` (default 300) | quick_scan + deep_dive | `*tools-raw.json` `floss.ioc_shaped_*` |
| G29 | **pe_imports high-signal map as a case artifact** | The deterministic high-signal import map is written to the case dir (`quick_scan/pe-imports.json`) next to the other quick-scan artifacts, guarded on real signals and no error — a failed run must never look like evidence of absence. Precondition for any future promotion of G20 to a blocking gate | always on | quick_scan | `quick_scan/pe-imports.json` |
| G30 | **RE agent skills** (loaded, not recalled) | Five cited, versioned reverse-engineering procedures the deep-dive agent loads on demand via the load_skill tool: re-methodology, unpack-and-verify, obfuscation-recognition, ghidra-sql-recipes, verdict-calibration. Methodology is a structural property, not a prompt convention: a gate can check a skill and a report can cite it, whereas prompt prose is re-summarised and drifts. Each skill declares what it does NOT cover. Attribution: internal KB chunks cited in sources.jsonl as provenance metadata, not resolvable links | load_skill (agent-callable) or the prompt index | deep-dive agent | agent history + skill provenance |
| G31 | **Depth mode** (opt-in, post-pipeline) | A separate run that follows the main pipeline and aims to understand HOW the sample works, not whether it is malicious. Produces a function map (`understanding.json`), never a verdict, and never gates the main pipeline. Terminates on a declared unknown set: every region carries `understood` / `partial` / not-reconstructed / not-explored with a reason and evidence citation. The ceiling consolidates rather than truncates, so a cutoff is a partial-but-honest map. State checkpoints atomically after every region for pause/resume | `REVAI_DEPTH=1`, `REVAI_DEPTH_CEILING_SECONDS` (default 7200s) | after the pipeline | `understanding.json`, cost summary |

| G35 | **Configurable stage timeouts** | The publish/audit stage timeouts are env-overridable (`REVAI_STAGE_TIMEOUT_PUBLISH` / `REVAI_STAGE_TIMEOUT_AUDIT`). | G37 | **Sample-identity exemption** | The analysed sample's own sha256 is no longer counted as an unverified indicator. Every report states it in Sample Metadata, but it is not in the tool-output corpus the claims are verified against, so it was flagged. Read from `REVAI_CASE_DIR`, never from the report's own `sha256:` line, so a claim cannot exempt itself | always on | publish/audit quality gate | `pipeline-audit.json` `claimed_ioc_verification.excluded_items` |
| G39 | **Capability-domain deep dive** (plan #20) | The deep dive runs as a LangGraph StateGraph with one node per capability domain (surface, persistence, C2/network, evasion, execution/injection, credential access, exfiltration, defense impairment, encryption/obfuscation) instead of one flat ReAct loop that was *asked* to self-check every domain. When nothing substantive is produced the path returns falsy and the flat engine runs, so a failure can never surface as a verdict-shaped result. | G38 | **Evidence-collection guidance** | The defender-guidance exemption covered inspect/clean verbs but not evidence-collection ones, so a path the report recommended *gathering data about* ("Resolution: execute the sample ... capture ... registry writes under `<path>`") was read as an assertion that the sample wrote there. Same speech act, now classified the same way. A sentence that asserts the write stays a claim and is still verified | always on | publish/audit quality gate | `pipeline-audit.json` `claimed_ioc_verification.guidance_references` |
